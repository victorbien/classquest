ClassQuest User Guide

Everything you need to use ClassQuest — a lightweight online course platform for students, teachers and administrators.

Research prototype. All content is synthetic sample data. ClassQuest is intended for demonstration, not for managing real courses, grades or personal records.

About this guide

This is the end-user manual for ClassQuest. It explains how to sign in, how each kind of user works day to day, and how to get the system running for a demonstration.

ClassQuest has three kinds of users:

S

Students

Browse published courses, open resources (documents, books and videos), and track what they have opened.

T

Teachers

Create courses, upload resources, arrange them, and publish courses so students can see them.

A

Administrators

Monitor system health, run demonstration controls, and browse every resource in the library.

Key concepts

A few terms are used throughout this guide.

Course
A container for related learning resources. A course has a title, description, category, an optional cover image, and a status.
Resource
A single learning item inside a course. Three types exist: Document, Book (a digital book) and Video. Each can carry an optional week or section label.
Course status
A course is one of: Draft only its teacher and administrators can see it; Published visible to students; Archived hidden from students again, with resources and history kept but no new resources allowed.
Resource processing
When a resource is uploaded it runs through a short automatic pipeline — Submitted → Queued → Processing → Completed — usually within a few seconds. Students only ever see resources that reach Completed.
My Progress
For students, this means resources opened, overall and per course. It is not a grade, score, or measure of mastery or lesson completion.

Getting started

Signing in

  1. Open ClassQuest in your browser at http://localhost:8080.
  2. Enter your email and password on the Login screen.
  3. Select Sign in. You land on the home screen for your role: students on Home, teachers on their Dashboard, administrators on Operations.

Demonstration accounts

Finding your way around

Every screen shares the same layout: a sidebar on the left with the pages for your role, and a top bar showing the current page and your account. The pages you see depend on your role:

RolePages in the sidebar
StudentHome · Courses · My Progress
TeacherDashboard · My Courses · Publish Resource · Operations
AdministratorOperations · Library

If you open a page that is not meant for your role, ClassQuest simply returns you to your own home page.

Signing out

Use the account control in the top bar to sign out. Your session token expires automatically after about an hour, so you may be asked to sign in again during a long session.

Student guide

As a student you can browse published courses, open their resources, and see your own progress. You cannot see draft or archived courses.

Home

The Home screen is your starting point. Once you have opened at least one resource, it shows a Continue where you left off shortcut.

Browsing courses

  1. Select Courses in the sidebar.
  2. You see every published course as a card, with its cover image (or a coloured placeholder), title, category, and your progress for that course (for example 3 / 4 resources opened · 75%).
  3. Select a course to open it.

Draft and archived courses are never listed for students.

Opening a resource

  1. Resources are grouped by their week or section label and shown in the order the teacher arranged them.
  2. Only completed resources appear.
  3. Select Open. The file opens in a new tab via a secure, time-limited link (valid about five minutes). If it expires, select Open again for a fresh link.

Tracking your progress

Select My Progress to see your overall totals, a coverage percentage, a breakdown by resource type and by course, and a Recently opened list.

Progress counts a resource the moment you open it — it reflects what you have looked at, not how well you understood it. Only completed resources in published courses are counted, so "opened" can never exceed "available".

Teacher guide

As a teacher you create courses, add resources, arrange and publish them, and manage each course through its lifecycle. You can only manage courses you created.

Dashboard

The Dashboard is your landing page. It summarises recent activity and the processing pipeline, and includes a My Courses card focused on the courses you own.

Creating a course

  1. Select My Courses → Create Course.
  2. Fill in Title, Description, Category, and an optional Cover image (PNG, JPEG or WebP up to 2 MB). Without one, a category-tinted placeholder is drawn.
  3. Select Save as draft. Students cannot see it yet.

Adding a resource

  1. Open one of your courses and select Add Resource.
  2. Choose the type: Document, Book or Video.
  3. Enter a title, an optional description, and an optional week or section label.
  4. Drag and drop a file, or browse for one. Keep demonstration files small.
  5. Select Upload & publish.

A Processing pipeline indicator moves through Submitted → Queued → Processing → Completed, usually within a few seconds. When it completes, the resource joins the course's ordered list.

Only the file type and size are checked. If a file is rejected, nothing is stored and you see a short message — just try a different file.

Arranging resources

On the course page you can reorder resources with the up/down arrows (new resources are added to the end) and edit a resource's details inline.

Publishing, archiving and restoring a course

  • Publish Course — moves a draft to published; students can now see it.
  • Return to draft — moves a published course back to draft, hiding it again.
  • Archive course — hides it from students immediately; resources and history are kept, but no new resources can be added.
  • Restore to draft — brings an archived course back to draft. (Archived cannot go straight to published — restore to draft first, then publish.)

Courses are deliberately lightweight: no enrolment (every student sees every published course), and no grades, quizzes, assignments, forums or certificates. Ordering uses up/down arrows, not drag-and-drop.

Administrator guide

Administrators focus on system health and on browsing the full library. Administrators can also manage any course, not just their own.

Operations

The Operations screen is the control centre for a demonstration. Key panels:

  • Service health — the status of each underlying service (database, object storage, message queue, monitoring and alerting).
  • Storage overview — how resource files are distributed across storage tiers.
  • Monitoring — the count of recent bad (HTTP 400) requests and the monitoring alarm state.

Library

The Library gives administrators a view of every resource across all courses, useful for an overview or spot checks.

Demonstration controls

The Operations screen (teachers and administrators) includes Demonstration Controls. Everything they create is clearly labelled demo/sample content so students never see it by accident.

ControlWhat it does
Seed demo catalogueCreates four sample courses (Cloud Computing, Applied Blockchain, Data Analytics published, and Cybersecurity Essentials draft) and uploads eleven resources through the normal pipeline. Running it again skips what already exists.
Induce processing failureDeliberately fails one resource to show automatic retries. After the third attempt it is marked Failed and moved to a dead-letter queue. The failing resource stays in a hidden draft course.
Simulate Glacier tieringMoves up to ten completed demo resources to the long-term "Glacier" tier immediately, instead of waiting for the 90-day rule.
Generate HTTP 400 burstSends a burst of deliberately bad requests to demonstrate monitoring. The monitoring panel switches to Threshold exceeded.
Local demonstration limits. When running locally a few cloud behaviours are simulated rather than fully reproduced: the monitoring alarm is not expected to change to the fired state, alert emails are never actually sent, and Glacier restore is not implemented (so opening a Glacier-tier resource may be refused — as real long-term storage behaves without a restore step). These are expected and labelled in the interface.

Running ClassQuest locally

This section is for the person setting up a demonstration.

What you need

  • Docker Desktop (with Docker Compose), running.
  • Node.js 20 or later — only on the host for the automated tests and helper scripts; the app runs inside Docker.
  • Ports 8080, 4000, 3306 and 4566 free.
  • No AWS account and no cloud cost — the cloud services are emulated locally.

Start the stack

# 1. Create your local settings file (defaults work as-is)
cp .env.example .env          # Windows PowerShell: Copy-Item .env.example .env

# 2. Build and start everything
docker compose up -d --build

# 3. Wait until app-tier and web-tier show "healthy"
docker compose ps

Then open http://localhost:8080 and sign in with a demonstration account.

Seed the sample content

From the interface (Operations → Demonstration Controls → Seed demo catalogue) or the command line:

npm run demo:seed

Stop or reset

docker compose down        # stop, keep data
docker compose down -v     # stop and DELETE all data
Warning: docker compose down -v permanently deletes the local database and stored files. Use plain docker compose down to keep your demo data.

Troubleshooting

SymptomLikely cause and fix
The page will not load at localhost:8080The stack may still be starting. Run docker compose ps and wait until app-tier and web-tier are healthy.
"Docker daemon" or "engine" errorsDocker Desktop is not running. Start it, wait for Engine running, then start the stack again.
A port is "already allocated"Another program uses port 8080, 4000, 3306 or 4566 (often a local MySQL on 3306). Stop it or free the port.
A student cannot see a courseThe course is in Draft or Archived status, or its resources have not finished processing. Publish and wait for Completed.
A resource will not openThe link may have expired (about five minutes) — select Open again. A Glacier-tier resource may be refused by design.
A newly uploaded resource is missingProcessing may still be running. Wait for Submitted → Queued → Processing → Completed.
The monitoring alarm never "fires"Expected locally — the emulator does not evaluate the alarm. The request count still updates and is labelled.
You were signed out unexpectedlySign-in tokens expire after about an hour. Sign in again.

Frequently asked questions

Is my data real?

No. ClassQuest is a prototype that uses only synthetic sample content, intended for demonstration — not for managing real courses or student records.

Does "My Progress" mean my grade?

No. Progress records which resources you have opened. It is not a grade, score, or measure of understanding or completion.

Why can't students enrol in a specific course?

By design there is no enrolment. Every student can see every published course.

Can a teacher edit another teacher's course?

No. Teachers manage only the courses they created. Administrators can manage any course.

Where can I learn how the system is built?

See the project's ARCHITECTURE.md and README.md for the technical design and how the prototype maps to a full cloud deployment.
